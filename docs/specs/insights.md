# Spec — Insights page (tutors)

Written 16 Nov 2026. Status: ready to build. **No schema change. Migration 063 is NOT used.**
Concept reference: `Main.dc.html` → "Insights" tab ("How your practice is doing": navy "On track for 2026" card, "Take-home by month" bars, "Your week" slot grid, "Close to finishing a cycle").

---

## 1. Plain-language summary for Hanyong

- A new **Insights** page shows how your practice is doing: take-home for each of the last 12 months (tap a bar to see that month and jump to its recap), what you have earned this year, and a clearly-labelled **estimate** of where you will end the year.
- It also shows which days and times you teach most, how full your open booking slots are, which students are about to finish a payment cycle, how long students stay with you, and how your income splits between direct students and agencies.
- Every money figure comes from the **same calculation as the monthly recap and the year-end report** (`buildEarningsBreakdown`). The page checks itself and shows a visible warning if the numbers ever disagree.
- Nothing changes for parents. Nothing is written to the database: the page only reads.
- Practice students are left out. Archived and deleted students still count in past months.
- No new chart library: the charts are plain coloured boxes, so the page stays light on a phone.
- Built in 4 small PRs. No SQL for you to run.

## 4. User stories and flows

**S1. See the year at a glance.** Tutor opens Insights. Navy card (concept: "On track for 2026") shows the year-end estimate, "earned so far", and one line on how the estimate is made. Tapping "How is this worked out?" expands the working, month by month.

**S2. Look at a month.** Under "Take-home by month" the tutor taps a bar (concept: "Tap a bar"). The bar turns navy and the panel under the chart shows that month's take-home, lessons taught, agencies' earnings and total billed. "Open October recap" goes to `/dashboard?recap=2026-10`, where the recap card shows October.

**S3. Understand agency income.** "Direct vs agency" card shows take-home from direct students, take-home from agency students, and what agencies earned (never reached you / commission you pay). Each agency row links to its statement.

**S4. Know who to bill next.** "Close to finishing a cycle" (concept card of the same name) lists students one lesson away from a bill, with a progress bar and the expected amount. Tapping a row opens the student profile.

**S5. See who stays.** "Your students" card: active count, typical tenure, how many of the students taught three months ago are still having lessons, and a "gone quiet" list.

**S6. See the week's shape.** "Your week" (concept card): a Mon–Sun grid by time band shaded by how often the tutor teaches there, the busiest day, and — if open slots exist — how full they are.

**S7. Read the takeaways.** Up to 3 short sentences at the top of the page, each produced by a fixed rule.

### 6.3 Loading (one function, `loadInsightsData(tutorId)`)

Create `src/lib/fetchAll.js`:

```js
// Reads every row of a query, 1,000 at a time. `build` must return a fresh
// query each call and must include a stable .order() ending in a unique column.
export async function fetchAll(build, pageSize = 1000) {
  const rows = [];
  for (let from = 0; ; from += pageSize) {
    const { data, error } = await build().range(from, from + pageSize - 1);
    if (error) throw error;
    rows.push(...(data ?? []));
    if (!data || data.length < pageSize) return rows;
  }
}
```

Queries (all with `.eq("tutor_id", tutorId)`):
1. `students` — `select("*")`, order `id`.
2. `payees` — `select("id, name, share_percent")`, order `id`.
3. `lessons` — **all dates, completed and not**, `select("id, student_id, lesson_date, lesson_time, duration_minutes, rate, rate_type, is_completed, payment_cycle_id")`, order `lesson_date` then `id`. Paged with `fetchAll`.
4. `payment_cycles` — `.in("status", ["pending","overdue"])`, order `id`. Paged.
5. `availability_windows` — `start_at >= {today-28d}T00:00:00+08:00` and `start_at <= {today+14d}T23:59:59+08:00`, order `start_at` then `id`. Paged. Build the timestamps as strings with `+08:00`; never `toISOString()`.

All five through `fetchAll`. If any throws, the page shows the error state.

## 7. Logic and edge cases

All logic lives in a new pure module `src/lib/insights.js` (no React, no Supabase), so it can be reasoned about and tested on its own. The page `src/pages/Insights.jsx` only loads, calls, and renders.

### 7.1 Dates and time zone
- `todayKey` = Singapore date: `new Intl.DateTimeFormat("en-CA", { timeZone: "Asia/Singapore" }).format(new Date())` → `"YYYY-MM-DD"`.
- `lesson_date` / `lesson_time` are Singapore wall-clock values. Compare them as strings. Never build a `Date` from them to decide a month or a day; month = `lesson_date.slice(0, 7)`.
- Day of week: `new Date(Date.UTC(y, m - 1, d)).getUTCDay()`.
- Date arithmetic (add days): do it on `Date.UTC` values and format back with `getUTC*`.
- `availability_windows` are timestamptz: convert to Singapore by `new Date(Date.parse(ts) + 8 * 3600_000)` and read `getUTC*` fields.
- `monthDate` passed to `buildEarningsBreakdown` is `new Date(year, monthIndex, 1)` (it only reads year and month).

### 7.2 Who and what counts
- **Practice students**: drop every student with `is_practice === true`, and all their lessons, cycles — before anything else.
- **Archived / deleted students**: kept for every historical figure (month bars, year-to-date, agency split, tenure history). Excluded from forward-looking items: booked lessons in the forecast, recent pace, cycle list, active counts, gone-quiet list.
- "Current student" = `!archived && !deleted_at && !is_practice`.
- **Completed** = `is_completed === true`. Ignore the `status` column.
- **Past, not marked done** (`lesson_date < todayKey`, not completed): not earned, not booked. Counted only for the nudge.
- **Booked** = not completed, `lesson_date >= todayKey`, `lesson_date <= {YEAR}-12-31`, current student.
- Lessons whose `student_id` is not in the loaded students: drop and `console.warn` once.
- Waived / overdue / paid status of cycles does **not** affect take-home (take-home is lessons taught, same as the year-end report). Only `pending`/`overdue` cycles are used, and only in 7.6.

### 7.3 Per-student month table (the single source of every money figure)
```
buildMonthTable({ monthKeys, students, payees, completedByStudent })
```
For each student and each `monthKey` in which that student has at least one completed lesson, call

```js
buildEarningsBreakdown({ monthDate, students: [student], payees, lessons: completedByStudent.get(student.id) })
```
and store, in **integer cents** (`Math.round(x * 100)`):
- `total` (bd.total), `mine` (bd.mine), `agency` (bd.agencyTotal)
- `kept` = sum of `line.amount` where `line.kind === "placement"` or `line.collectedBy === "agency"` (set-up A and placement fees)
- `commission` = sum of `line.amount` where `line.collectedBy === "me"` (set-up B)
- `agencies` = `[{ name, payeeId, cents }]` from `bd.agencies`
- `lessons` = number of that student's completed lessons in the month

`lessons` passed in must be that student's **whole** completed history (placement fees drain from the earliest lessons).

Month totals are sums over students. Take-home for a month = Σ `mine`. This is what the recap calls "My take-home" and what the year-end report calls `mine` (its "Revenue" = `mine + commission`).

Do not write any other fee, share or rounding arithmetic.

### 7.4 Year-to-date and forecast (the estimate)

Constants at the top of `insights.js`:
```js
export const RUN_RATE_FACTOR = 0.8;   // count only 80% of recent pace
export const RUN_RATE_MONTHS = 2;     // last two full months
```

- `YEAR` = year of `todayKey`. Months `Jan..Dec` of `YEAR`; `cur` = current month.
- **Earned(m)** = Σ `mine` for month m from the table (completed lessons).
- **YTD** = Σ Earned(Jan..cur).
- **With-calendar table**: build a second month table for months `cur..Dec` where each current student's lesson list = completed lessons + booked lessons with `is_completed` set to `true` on a copy. **On calendar(m)** = that table's Σ `mine` for m − Earned(m). (Running booked lessons through the same function applies agency shares and placement fees correctly.)
- **Recent pace** — only if both of the two full months before `cur` have at least one completed lesson (any student):
  `dailyPace = (Σ mine of current students over those two months) / (days in those two months)`.
  Otherwise `dailyPace = null` ("Calendar only" mode).
- **Days left(m)**: for `cur`, days after today to month end; for later months, days in the month.
- **Pace(m)** = `round(RUN_RATE_FACTOR * dailyPace * daysLeft(m))` cents, or 0 when `dailyPace` is null.
- **Counted(m)** = Earned(m) + max(On calendar(m), Pace(m)).
- **Forecast** = Σ Earned(Jan..month before cur) + Σ Counted(cur..Dec).
- **Calendar-only figure** = YTD + Σ On calendar(cur..Dec) (shown as "already on your calendar").
- Current-month estimate for the chart = Counted(cur).

Why this is conservative: booked lessons count once; where the calendar is thinner than usual the page tops up to only 80% of the recent pace; students who have left do not feed the pace; nothing is assumed to grow. It does not know about school holidays — the card says "Estimate".

Edge cases: December → only the rest of December is estimated. 31 Dec → forecast = YTD. January with little history → "Calendar only". A tutor whose pace months are in the previous year still gets a pace (the table covers them, see 7.5).

### 7.5 Month keys to build
`monthKeys` = union of: the 12 chart months (cur−11 … cur), Jan..Dec of `YEAR`, the two pace months. Build the table once and read everything from it.

### 7.6 Close to finishing a cycle
Current students only. `open` = that student's completed lessons with `payment_cycle_id === null` (same definition as `openCountByStudent` in `Dashboard.jsx`). `upcoming` = their booked lessons sorted by date, time. Skip a student who has any `pending`/`overdue` cycle (they belong on the Payments page). Skip `per_lesson`.

- **`lessons` mode** (N = `payment_cycle_count ?? 4`): include when `open.length >= 1` and `N - open.length <= 1` and `open.length < N`. Progress `open.length / N`, shown as `{k} of {N}`.
  Amount = Σ `lessonAmount` of the open lessons + the next `N − k` upcoming lessons (if booked).
  Note: completing lesson booked → `One more lesson on {Thu 19 Nov}, then bill {$1,200}.`; not booked → `One more lesson to go — nothing booked yet.`
- **`monthly`**: include when today is within the last 7 days of the month and the student has ≥ 1 completed unbilled lesson this month. Progress = day of month / days in month. Count text `{n} lessons`. Note: `Monthly — bill {$X} after {30 Nov}.` (X = open lessons this month + booked lessons this month).
- **`custom_date`** (day = `payment_custom_day ?? 1`, clamped to month length): include when the next due date is 0–7 days away and there is ≥ 1 completed unbilled lesson. Note: `Bill {$X} on {5 Dec}.`
- If the student has `payee_id` and `fee_collected_by === "payee"`: append ` {Agency name} collects this.`
- Sort: `lessons` mode first by fewest lessons to go, then by date of the completing/billing day, then name.
- Amounts use `lessonAmount` from `src/lib/paymentMode.js` (the parent-facing bill, before any agency share).

### 7.7 Retention and tenure
Per non-practice student with ≥ 1 completed lesson: `first` / `last` = earliest / latest completed `lesson_date`.
- **Active** = current student AND (`last >= today − 45 days` OR has a booked lesson).
- **Tenure (months)** = whole months from `first` to `today` for active students = `(y2−y1)*12 + (m2−m1)`, minus 1 if day-of-month of today < day-of-month of `first`; minimum 0.
- **Typical time with you** = median tenure of active students (average of the two middle values, rounded down); `Under a month` when 0.
- **Buckets** (active): `<3`, `3–5`, `6–11`, `12+` months.
- **Still with you after 3 months**: cohort = non-practice students with ≥ 1 completed lesson in the calendar month three months before `cur`; numerator = cohort members who are Active. Tile shows `K of N`; `—` when N = 0.
- **Gone quiet** = current students with ≥ 1 completed lesson, `last < today − 30 days`, no booked lesson. Sorted by `last` ascending.

### 7.8 Busiest days, time bands, open-slot utilisation
- Window = the 56 days ending yesterday. Use completed lessons of all non-practice students (archived/deleted included — it is history).
- Day counts: lessons per weekday. Band counts: per weekday × 2-hour band, band index = `floor(hour / 2)` from `lesson_time.slice(0, 2)`; a lesson is counted in the band where it **starts**. Lessons with null `lesson_time` add to the day only.
- Busiest day = highest count (tie → earlier in the week). Busiest time = band with the highest total across days. Need ≥ 4 lessons in the window to show the grid.
- **Utilisation** — windows with `start_at` from today−28 d to today+14 d:
  - `openMinutes` = Σ window lengths.
  - `filledMinutes` = minutes inside any window that are covered by a lesson (completed or booked, any non-practice student, `lesson_time` not null, interval `[start, start + duration_minutes)` on the same Singapore date). Merge overlapping lesson intervals per day before intersecting so no minute counts twice.
  - Show only when `openMinutes >= 120`. Percentage = `round(filled / open * 100)`, hours shown rounded to the nearest whole hour.
  - This matches how `/book/:token` works: `netlify/functions/booking-page.js` subtracts lessons from windows to find free time; confirming a booking creates a lesson and leaves the window row in place.

### 7.9 Numbers check (replaces the year-end report's self-comparison)
Run on every load, in cents, in `runInsightsChecks()`. Return a list of failed check codes.

| Code | Check (two independent routes must agree exactly) |
|---|---|
| C1 | For each chart month: Σ over students of the per-student table (`total`, `mine`, `agency`) **equals** one `buildEarningsBreakdown` call with **all** non-practice students and all completed lessons for that month (the exact call the recap card makes). |
| C2 | For each chart month: Σ `total` **equals** Σ `Math.round(lessonAmount(l, student) * 100)` over completed non-practice lessons with `lesson_date` in the month. |
| C3 | For each table cell: `total === mine + agency` and `agency === kept + commission`. |
| C4 | Direct take-home + agency-student take-home (7.10) **equals** Σ `mine` over the 12 chart months. |
| C5 | `Forecast >= calendar-only figure >= YTD >= 0`. |

On any failure: `console.error("[Insights] numbers check failed", codes, details)` **and** show an amber box at the top of the page on every environment:
`These figures didn't pass our own double-check ({codes}). Please don't rely on them yet — send this message to support.`
(Hanyong tests by clicking previews, so a console-only check would never be seen.)

### 7.10 Direct vs agency split (12 chart months)
From the month table, per cell: if `agency > 0` the cell is an **agency** cell, else **direct**.
- Direct take-home = Σ `mine` of direct cells.
- Agency-student take-home = Σ `mine` of agency cells.
- Agencies earned = Σ `agency`; of which Kept = Σ `kept` (set-up A + placement fees), Commission = Σ `commission` (set-up B).
- Per agency: group `agencies` by lower-cased name; keep `payeeId` and the latest month with earnings.
A student whose placement fee has been fully paid off moves from "agency" to "direct" from the next month on — this is intended (it reflects where the money actually went).

### 7.11 Takeaways (fixed rules, no AI)
Evaluate in this order; show the first 3 that fire. `L` = last full month, `P` = the month before it.

| # | Fires when | Sentence |
|---|---|---|
| T1 | ≥ 1 past lesson not marked done (current students) | `{n} past lesson(s) aren't marked done yet, so they aren't counted here.` + link `Review →` `/dashboard` |
| T2 | Gone-quiet list has ≥ 1 | `{n} student(s) have nothing booked and no lesson for over 30 days.` |
| T3 | Earned(L) > 0, Earned(P) > 0, change ≥ 10% either way | `{L} take-home was {x}% higher/lower than {P} ({+/−$d}).` |
| T4 | L is in `YEAR`, ≥ 3 months of `YEAR` have earnings, Earned(L) is the strict maximum | `{L} was your best month this year.` |
| T5 | Agencies earned ≥ 10% of total billed over the 12 months | `Agencies earned {x}% of what you billed in the last 12 months ({$y}).` |
| T6 | ≥ 8 lessons in the 8-week window and busiest day ≥ 25% of them | `{Mondays} are your busiest day ({n} lessons in the last 8 weeks).` |
| T7 | Utilisation shown and ≥ 85% | `Your open slots are almost full ({x}%).` |
| T8 | Utilisation shown and ≤ 40% | `Less than half of your open slots are filled ({x}%).` |

Percentages rounded to whole numbers; money in whole dollars. Singular/plural handled.

## 12. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Insights and the recap disagree. | One source (`buildEarningsBreakdown`), integer cents, checks C1–C4 compare independent routes and show a visible warning; acceptance test 6 compares to the cent. |
| Practice-student migration (059) lands before or after this. | `select("*")` + JS filter works in both orders (F3). Equality with the recap for practice students depends on the recap applying the same exclusion (owned by the 059 work). |
| Tutor reads the forecast as a promise. | "Estimate" pill, method line always visible, expandable working, 80% factor, no growth assumed, footer disclaimer. |
| Availability windows are barely used (1 row live), so utilisation would look broken. | Hidden behind a 2-hour minimum with a helpful empty state; the grid is driven by lessons. |
| More than 1,000 lessons. | `fetchAll` paging with a stable order on every query; partial load = error state. The Dashboard recap itself is not paged (F7) — separate fix recommended. |
| Time-zone slips (device not on Singapore time, UTC conversions). | Rules in 7.1: string comparison for lesson dates, `+08:00` strings, no `toISOString()`. |
| Phase 2 touches the 2,000-line Dashboard. | Change limited to one hook call and one prop on two existing elements; isolated in its own PR with tests 12–15. |
| Per-student × per-month calls are slow for large tutors. | Calls are skipped for months where the student has no completed lesson; each call only sees that student's lessons. |
| Weaker model re-implements fee maths. | Spec and every prompt forbid it; C2/C3 catch drift. |
| Cross-domain leakage. | Tutor-only route and nav; explicit `tutor_id` filter (F10); no agency or practitioner file edited. |
